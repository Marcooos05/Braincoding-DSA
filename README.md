# Braincoding-DSA
Going back to appreciate the process of Data Structures and Algorithm because vibe-coding has stolen all the joy of learning. This is my personal journal for DSA coding session, something that I used to enjoy doing for the fun of it. However with AI vibe-coding and rapid software development, it has been rather dreadful to code or more like read and approve code...

## Motivation
Hi, I'm Marcus. 

I initially got into coding when I was interested in data analytics and big data stuff, which was roughly 6 years ago, pre-ChatGPT and pre-covid. Since then, I actually matriculated into SUTD to take a computer science degree. And honestly, having entered freshmore pre-ChatGPT and now entering my final year with Claude... Expectations have changed tremendously, I find that undergrads have been thrown into a deep abyss with a super tool and hence we are expected to know everything, almost like expecting someone to author a book because they own a dictionary, quite ridiculous if you think about it

Anyway, having also helped out as a teaching assistant to teach younger students how to code and program, it's quite sad to see them all depending on AI to write simple odd_or_even functions. It seems that everyone is now forced to know about coding but only some actually appreciate the intricacies of programming. Everyone is so focused on the outcome and the end goal, that they forget to enjoy the process. They fail to understand that life is meant to be lived through the journey and not just the destination. We get to live life every single day, not only on good days, but especially on bad days where debugging takes 12 hours, and certainly not only when we are successful - which in the world of software development, basically never exists. 

## My Personal Rules
### *'Education without application is just entertainment'*
1. Back to basics DSA - Attempting before reviewing solutions
>The goal of DSA is about learning and understanding how to use the fundamentals of programming to problem solve, a skill which I would argue is often overlooked and greatly undervalued in this age of fast-paced AI code generation. And I firmly believe in the idea that learning is painful, it is meant to be painful because the most valuable and memorable lessons are learnt through adversities and hardship. One of the things we neglect is that learning is meant to be SLOW. Ever heard of the 10,000 hours, it takes minimally 10,000 hours of DELIBERATE practice to achieve mastery in complex skills. With AI, things get faster at the expense of being intentional and deliberate which is why many knowing but not many are capable of application.

2. No using of AI for coding, only using AI as a ultra-search engine like Stack Overflow, RIP SO...
>This is certainly vague and purely up to interpretation for each user, but personally I will be using AI mainly for checking of syntax and understanding computing concepts better - with the endless YouTube videos explaining each Leetcode I really don't think I will be using AI to understand algorithms tbh. Algorithms should be entirely understood by me before I submit any coded solution, and that might take a long time and less 'efficient' than AI coding, but who cares... I'll probably realize that I'm quite stupid and horrible at coding without AI but I find this to be a rather humbling experience, to embrace failure and accept challenges head-on.

3. Ain't coding unless I want to do it, no schedule, no targets, all vibes
>This project is entirely for fun and learning, not for a job interview assessment or chasing a leetcode streak. Those are absolutely valid reasons to practice, but personally this is for me to rediscover the joy of coding and problem solving, which has been lost heavily since vibe-coding was a thing. I'm not against vibe-coding but God bless it's literally brainrot for coders.
